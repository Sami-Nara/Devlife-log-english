IntroHello everyone! We are Sarly and Emmanuel, and this is our Debugging Log about SICUA, our university access control system.

Part 1 · IncidentLast Thursday evening, the server crashed at ten p.m. Before the crash, we had been working on the production environment for four hours. We had been attempting to deploy a new update, and we had been compiling the core repository for nearly two hours.

Question 1So, what had we been doing before we found the bug? We had been analyzing CPU spikes, and we had been ignoring some minor warnings in the database.

Emmanuel

Part 2 · EvidenceNow we are going to show our evidence. First, this is our GitHub commit: it says we fixed a memory leak that had been causing database crashes. Second, this is the server error message: the memory ran out and the service stopped. Third, this is the Slack message we sent to our team about the problem in SICUA.

Question 2And how long had we been working when the system crashed? We had been working for four hours, and our team had been analyzing CPU spikes since eight a.m.

ClosingAn unoptimized query had been running in the background and using all the memory. Finally, we debugged the code, applied a hotfix patch, and restored all services. Thank you!
